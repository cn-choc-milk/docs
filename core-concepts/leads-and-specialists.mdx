## What it is

Leads and specialists are Synapse's Salesforce-specialist agents. Each has a defined role, skill set, and area of expertise within the Salesforce delivery domain. They execute Blueprint tasks inside isolated Execution Nodes — generating code, reviewing outputs, analyzing dependencies, and running quality gates — under human oversight and approval.

Leads and specialists do not act autonomously. Every task they produce passes through the Sentinel quality pipeline. Human reviewers approve gated actions through Nexus before execution proceeds to the next phase.

## When to use it

Leads and specialists are assigned to Blueprint tasks and activated when a Run starts. You interact with them directly through the Nexus assistant panel — ask for impact analysis, architecture guidance, or a code review before formally creating a Blueprint and starting a Run.

## Salesforce delivery example

A delivery team receives a Jira Signal for a complex CPQ quoting-flow change. Jira Autopilot creates a Blueprint with five tasks. AXIOM is assigned to the architecture design task. FORGE is assigned to three Apex implementation tasks. CURATOR is assigned to the code review task. When the Run starts, each specialist executes their task in an isolated Execution Node. SENTINEL validates every output. The delivery lead approves each gated phase transition in Nexus.

## Required access

- **Synapse role:** Project Member or higher to interact with leads and specialists via Nexus
- **Project or POD membership:** For Run-based execution, the user must be a project or POD member
- **Salesforce connection:** Leads and specialists with metadata analysis tasks require an active org connection

## Governance notes

Leads and specialists execute inside isolated Execution Nodes. They can read org metadata via the Metadata Intelligence Engine, but they do not directly modify your production Salesforce org. Code generated by specialists is committed to a feature branch and must be reviewed and merged by a human. The Sentinel quality pipeline validates all outputs before they are surfaced for human approval.

## The specialist roster

### Architecture Lead — AXIOM

Handles solution architecture, integration design, and system planning for complex Salesforce changes. Best for: designing multi-object data models, evaluating integration patterns, and planning large metadata deployments.

### Build Specialist — FORGE

Generates Apex classes, triggers, Lightning Web Components, and Flow configurations. Best for: code generation from approved specifications, implementing data transformations, and building automation logic.

### Data Modeling Specialist — SYNTH

Designs object schemas, field definitions, relationship structures, and data migration mappings. Best for: schema design reviews, migration planning, and data quality analysis.

### Code Reviewer — CURATOR

Reviews specialist-generated code against Salesforce best practices, security standards, and organizational conventions. Best for: pre-merge code quality gate, identifying PMD violations, and security scan review.

### Governance Specialist — GUARDIAN

Analyzes governor limit budgets, CI/CD configuration, deployment dependencies, and compliance flags. Best for: pre-deployment risk analysis, governor limit diagnostics, and change management impact assessment.

### Integration Specialist — RELAY

Handles API integrations, external system connections, data mapping between systems, and webhook configurations. Best for: Salesforce-to-external-system integration design, middleware configuration, and event-driven architecture.

### Quality Pipeline — SENTINEL

Runs the nine-gate quality validation pipeline on all specialist-generated code. SENTINEL is not directly invoked by users — it runs automatically during every Run. See [Sentinel quality pipeline](/security-governance/approval-gates) for gate details.

## How specialists execute

When a Run starts, the orchestration system:

1. Reads the approved Blueprint and its task assignments.
2. Provisions isolated Execution Nodes for each task.
3. Dispatches tasks to the assigned specialists.
4. Routes each task output through the Sentinel quality pipeline.
5. Surfaces approved outputs for human review at gated phase transitions.

```text
Blueprint approved
   → Run started
   → Tasks dispatched to assigned specialists
   → Specialists execute in isolated Execution Nodes
   → Sentinel gates validate each output
   → Human approval at gated transitions in Nexus
   → Run completes with artifacts and audit trail
```

## Multi-specialist coordination

Complex Blueprints involve multiple specialists working in parallel or in sequence. Dependencies in the Blueprint control the order — AXIOM's architecture output must be approved before FORGE begins implementation. The orchestration system respects dependency ordering automatically.

## Interacting with specialists

Open the Nexus assistant panel (right sidebar) to interact with leads and specialists before starting a Run:

- Ask AXIOM: "What are the risks of adding a new lookup field to the Opportunity object?"
- Ask GUARDIAN: "Review this Apex trigger for governor limit risks at 200 records."
- Ask SYNTH: "Suggest a data model for tracking multi-currency revenue recognition."

Responses include analysis, recommendations, or generated artifacts. Use **Apply** to add specialist suggestions directly to your Blueprint.

## Monitoring specialist activity

1. Open **Nexus** from the sidebar.
2. The dashboard shows active specialists, their current tasks, execution timeline, recent completions, and failures.
3. Click any active specialist to see detailed task logs.
4. Use **Stop** to cancel a running task and return it to the queue for reassignment.

## Tips and best practices

- **Trust but verify.** Leads and specialists are capable but always review generated code before approving it for deployment.
- **Be specific.** Detailed Blueprint task descriptions produce better specialist output than vague prompts.
- **Use the right specialist.** Do not assign architecture decisions to FORGE; use AXIOM. Assign code review tasks to CURATOR, not FORGE.
- **Monitor actively.** Check Nexus during long-running Runs for early issue detection and faster gated approvals.
- **Provide context.** Specialists perform better when the Blueprint includes project metadata, Spec Explorer entries, and MIE analysis results.
