title: "Authenticate with the Synapse API using Bearer tokens"
description: "Learn how to retrieve a Bearer token from the Synapse dashboard, pass it in the Authorization header, and resolve 401 and 403 errors."
---

Every Synapse API endpoint — except the health check — requires a Bearer token. You get this token from the Synapse dashboard after signing in, and you include it in an `Authorization` header on each request. This page explains how to retrieve your token, use it, and understand what to do when authentication fails.

## Get your Bearer token

When you sign in to the Synapse dashboard, the platform creates a session and issues an access token tied to your account. This token is what you pass to the API.

<Steps>
  <Step title="Sign in to the dashboard">
    Go to [synapse-architect.com](https://synapse-architect.com) and sign in with your credentials.
  </Step>
  <Step title="Open your account settings">
    Click your avatar in the top-right corner and select **Settings → API Access**. Your current session token appears here.
  </Step>
  <Step title="Copy your access token">
    Click **Copy token** next to your active session. This is the value you'll use in the `Authorization` header.

    <Warning>
      Treat your access token like a password. Don't commit it to version control or share it in public channels. If you suspect a token has been exposed, sign out of your session to invalidate it and sign back in to generate a new one.
    </Warning>
  </Step>
</Steps>

<Note>
  Tokens expire after a period of inactivity or when you sign out. If you're building a long-running integration, re-authenticate periodically to get a fresh token rather than hard-coding a static value.
</Note>

## Make an authenticated request

Include your token in the `Authorization` header on every API request. The format is:

```
Authorization: Bearer <your-token>
```

### Examples

<CodeGroup>

```bash curl
curl https://api.synapse-architect.com/api/composio/connected-accounts \
  -H "Authorization: Bearer ${SYNAPSE_TOKEN}"
```

```typescript TypeScript
const response = await fetch(
  'https://api.synapse-architect.com/api/composio/connected-accounts',
  {
    headers: {
      Authorization: `Bearer ${process.env.SYNAPSE_TOKEN}`,
    },
  }
);

const data = await response.json();
console.log(data);
```

</CodeGroup>

Store your token in an environment variable (`SYNAPSE_TOKEN` in the examples above) rather than inlining it in code.

## Understand authentication errors

When a request fails due to authentication, the API returns a standard error body:

```json
{
  "error": "Unauthorized",
  "message": "Invalid or missing token",
  "code": "AUTH_REQUIRED",
  "details": {}
}
```

| Status code | Meaning | How to fix |
|-------------|---------|------------|
| `401 Unauthorized` | Your token is missing, malformed, or expired. | Sign in to the dashboard to get a fresh token. Confirm you're passing it as `Authorization: Bearer <token>`, not `Bearer<token>` (the space matters). |
| `403 Forbidden` | Your token is valid, but your account doesn't have permission to access this resource. | Check that you're using the correct account. Some endpoints require a Professional or Enterprise plan. Contact support if you believe this is an error. |

<Warning>
  A `401` on a request that previously worked usually means your session has expired. Re-authenticate to get a new token — do not retry indefinitely with the same token.
</Warning>

## Rate limits

Each successful authenticated request counts against your plan's rate limit:

| Plan | Limit |
|------|-------|
| Free | 100 requests / hour |
| Professional | 1,000 requests / hour |
| Enterprise | 10,000 requests / hour |

Every API response includes rate limit headers so you can track your usage:

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | Maximum requests allowed in the current window |
| `X-RateLimit-Remaining` | Requests left before you hit the limit |
| `X-RateLimit-Reset` | Unix timestamp when the limit resets |

When you exceed your limit, the API returns `429 Too Many Requests`. Wait until the `X-RateLimit-Reset` time before retrying.
