If you are evaluating Synapse or just getting started, this page covers the questions that come up most often. If you have a question that is not answered here, reach out through the in-app **?** menu or visit the community forum.

<AccordionGroup>

  <Accordion title="What Salesforce editions and org types does Synapse support?">

    Synapse works with any Salesforce org that supports the Metadata API and has API access enabled. This includes:

    - **Enterprise Edition** and above (production orgs)
    - **Developer Edition** orgs
    - **Sandbox orgs** (Full Copy, Partial Copy, Developer, Developer Pro)
    - **Scratch orgs** created by Salesforce DX

    Synapse does not support **Essentials** or **Professional Edition** orgs unless the org has the API add-on enabled, because those editions do not expose Metadata API access by default. If you are unsure whether your org qualifies, connect it in **Settings → Connections** — Synapse will surface a clear error if the required APIs are unavailable.

    <Note>
      Government Cloud and Healthcare Cloud orgs with IP allowlisting requirements may need additional configuration. Contact support before connecting those org types.
    </Note>

  </Accordion>

  <Accordion title="Does Synapse store my Salesforce credentials?">

    No. Synapse uses OAuth 2.0 to connect to Salesforce. When you authorize the connection, Salesforce issues Synapse an access token and a refresh token — your username and password are never sent to or stored by Synapse.

    The access token is used to make API calls on your behalf. The refresh token is encrypted at rest and used only to obtain a new access token when the current one expires. You can revoke Synapse's access at any time from **Salesforce Setup → Connected Apps → Synapse**, which immediately invalidates both tokens.

  </Accordion>

  <Accordion title="How is data isolated between tenants?">

    Every Synapse workspace operates in its own isolated tenant. Your Salesforce metadata, action plans, agent outputs, and configuration are stored under a unique tenant ID, and all database queries are scoped to that ID using row-level security (RLS) policies enforced at the database layer.

    Synapse agents run in ephemeral, per-execution sandbox environments. Each execution gets a fresh, isolated environment that is destroyed after the run completes — no data from one execution persists into another, and no data crosses tenant boundaries.

    Synapse does not use your data to train AI models.

  </Accordion>

  <Accordion title="What AI models power the Synapse agents?">

    Synapse agents use large language models from leading AI providers. The specific model powering each agent may vary based on the task type — reasoning-heavy tasks (such as impact analysis and architecture planning) use models optimized for complex reasoning, while code generation tasks use models fine-tuned for software development.

    You can see which model was used for any given agent run in the execution logs. Go to the completed task node, open the **Last Run** tab, and look for the `model` field in the run metadata.

  </Accordion>

  <Accordion title="Can I use my own OpenAI or Anthropic API key?">

    Yes. Synapse supports bring-your-own-key (BYOK) for OpenAI and Anthropic. When you configure your own key, agent runs are billed directly to your AI provider account rather than consuming Synapse's shared model capacity.

    To configure your key:

    <Steps>
      <Step title="Open LLM provider settings">
        Go to **Settings → Configuration → LLM Providers**.
      </Step>
      <Step title="Add your key">
        Select **OpenAI** or **Anthropic**, paste your API key, and click **Save**.
      </Step>
      <Step title="Verify the connection">
        Click **Test Key** to confirm Synapse can reach the provider with your credentials.
      </Step>
    </Steps>

    <Note>
      BYOK is available on the Pro plan and above. On the Free plan, all agent runs use Synapse's shared model capacity within the monthly usage limit.
    </Note>

  </Accordion>

  <Accordion title="How do agents push code back to my repository?">

    When you connect a GitHub repository to a Synapse project, agents are authorized to create branches and open pull requests on your behalf using a GitHub App installation. Agents never push directly to your main or protected branches.

    For each agent execution that produces code:

    1. The agent creates a new branch named `synapse/<run-id>` (or a custom prefix you configure in project settings).
    2. All generated files are committed to that branch.
    3. A pull request is opened against the base branch you specify, with the agent's reasoning and a summary of the changes in the PR description.
    4. Your normal review process — including branch protection rules, required reviewers, and CI checks — applies to the PR before anything can be merged.

    You can also configure Synapse to skip the PR step and only push the branch, if you prefer to open PRs manually.

  </Accordion>

  <Accordion title="What happens if an agent's code fails review?">

    If a reviewer requests changes or your CI pipeline fails, you have two options:

    - **Iterate with the agent**: Add a new task to the action plan describing the requested changes, run it, and the agent commits additional changes to the same branch.
    - **Edit manually**: Check out the branch, make your changes locally, and push. Synapse tracks the branch by run ID, so manually pushing additional commits does not break anything.

    If a PR is closed without merging, Synapse marks the corresponding execution node as **Cancelled** in the action plan. You can re-run the task at any time to generate a fresh branch and PR.

    <Note>
      Approvals are final in Synapse's action plan system — you cannot un-approve an already-approved node. If you need to revert an approval decision, reject the downstream task instead and re-run the relevant steps.
    </Note>

  </Accordion>

  <Accordion title="Is there a free tier? What are the rate limits?">

    Yes, Synapse has a free tier. The free plan includes:

    - A limited number of agent task executions per month
    - Access to Quick and Smart impact analysis modes
    - Connection to one Salesforce org and one GitHub repository
    - Shared model capacity (no BYOK)

    Paid plans increase execution limits, enable Comprehensive analysis, allow multiple org connections, and unlock BYOK for your own AI provider keys.

    Rate limits apply to the Synapse REST API on all plans. If you hit a `429 Too Many Requests` response, the `Retry-After` header in the response tells you how long to wait before retrying. See the [API rate limits](/api/rate-limits) page for per-plan limit details.

    To see your current usage and available executions, go to **Settings → Billing**.

  </Accordion>

  <Accordion title="How do I cancel or pause a running execution?">

    You can pause or stop a running action plan from the execution controls panel in the top-right corner of Execution Mode.

    **To pause**: Click **Pause**. Any task nodes currently in progress will finish their current step before pausing — no partial work is lost. The plan status changes to **Paused**, and you can resume by clicking **Execute** at any time.

    **To stop completely**: Click **Reset** to halt execution and return all nodes to **NotStarted** status. Use this only if you want to discard progress and start from the beginning.

    To cancel a single stuck task without stopping the whole plan, right-click the task node in Execution Mode and choose **Skip**. The node is marked as **Skipped**, and downstream tasks that do not depend on it continue normally.

    <Warning>
      **Reset** cannot be undone. It clears all execution state for the plan. If you only need to wait for a blocked step to resolve, use **Pause** instead.
    </Warning>

  </Accordion>

  <Accordion title="Can I use Synapse without connecting GitHub?">

    Yes. GitHub is optional. Without a connected repository, agents still generate code and you can view, copy, or download the output directly from the task node detail panel in Synapse. You will not get automated branch creation or pull requests, but the generated code is fully accessible.

    Some features that require a repository connection:

    - Automatic branch creation and PR opening after agent runs
    - CI/CD pipeline integration
    - Version history tied to Git commits

    You can connect a GitHub repository later at any time from **Settings → Integrations → GitHub** without needing to reconfigure your Salesforce connection or recreate your projects.

  </Accordion>
