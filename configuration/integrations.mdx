---
title: 'Connect external tools and integrations to Synapse'
description: 'Link Jira, GitHub, Slack, and other external services to Synapse so Salesforce-specialist leads and specialists can read, create, and update work items across your existing tools.'
---

Synapse connects to the tools your team already uses so Salesforce-specialist leads and specialists can work with real project data rather than operating in isolation. When you connect Jira, for example, a specialist building a Blueprint can create Jira issues directly and sync status changes back to Synapse as work progresses. Connections are per-workspace and use OAuth so your credentials stay with your provider accounts — Synapse receives a token, not your password.

## Available integrations

<CardGroup cols={2}>
  <Card title="Jira" icon="ticket">
    Bidirectional sync between Synapse Blueprints and Jira issues. Specialists can create, read, and update Jira tickets. Status changes in either system are reflected in the other.
  </Card>
  <Card title="GitHub" icon="github">

  </Card>
  <Card title="Slack" icon="slack">

</CardGroup>

Additional integrations — Confluence, Microsoft Teams, and Azure DevOps — are available through the same connection flow.

## Manage connections

All integrations are managed from **Settings → Integrations**. The page shows every available integration and its current status: not connected, pending, active, or expired.

To add or remove a connection:

<Steps>
  <Step title="Open Settings → Integrations">
    In the left sidebar, go to **Settings**, then select **Integrations**.
  </Step>
  <Step title="Click Connect on the integration you want to add">
    Each integration tile shows a **Connect** button if no active connection exists for your workspace.
  </Step>
  <Step title="Complete the OAuth flow">
    Synapse opens the provider's authorization page in a new window or popup. Sign in to the provider and grant the requested permissions. After you approve, the provider redirects back to Synapse and the connection status updates to **Active**.
  </Step>
  <Step title="Confirm the connection is active">
    The integration tile updates to show the connected account and a **Disconnect** button. Active connections are available to all specialists in your workspace immediately.
  </Step>
</Steps>

<Note>
You need workspace admin permissions to add or remove integrations. Team members can use connected integrations through specialists but cannot modify connections.
</Note>

## Jira integration

Connecting Jira enables bidirectional sync between Synapse Blueprints and your Jira project. When a specialist builds a Blueprint, it can create corresponding Jira issues automatically. As tasks are completed in Synapse, the linked Jira issues are updated to match.

**What Synapse can do with Jira:**

Salesforce-specialist leads and specialists can read, create, and update Jira work items as part of a governed Blueprint Run. Specifically:

- Create issues from Blueprint tasks, preserving title, description, and priority.
- Retrieve issue details so specialists have current context when working on a task.
- Update issue status and fields as work progresses.
- Search issues using JQL so specialists can find related work before creating duplicates.

When you connect Jira, you are prompted to enter your Atlassian subdomain. For example, if your Jira URL is `acme.atlassian.net`, enter `acme`.

<Note>
Synapse creates Jira issues on behalf of the connected account. Issues created by specialists appear in Jira attributed to the user who authorized the connection.
</Note>

## GitHub integration

The GitHub integration lets Synapse specialists respond to pull request events through a webhook. When a PR is opened or updated in a connected repository, Synapse receives the event and can trigger specialist analysis automatically.

**What Synapse can do with GitHub:**

Specialists can work with real repository data as part of a governed Blueprint Run:

- Analyze pull request diffs and surface potential issues.
- Leave review comments on specific lines.
- List branches and repository metadata for context during planning.

Setting up the GitHub integration connects your GitHub account. To enable PR analysis for a specific repository, configure the webhook in your repository settings to point to your Synapse workspace's webhook URL. You can find this URL in **Settings → Integrations → GitHub** after connecting.

## Disconnect an integration

To remove a connection, go to **Settings → Integrations**, find the active integration, and click **Disconnect**. The connection is removed immediately and specialists lose access to that service. No data created through the integration (such as Jira issues) is deleted — disconnecting Synapse does not affect records already created in the external system.
