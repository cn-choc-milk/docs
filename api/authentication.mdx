---
title: 'Authenticate and authorize Synapse API requests'
description: 'Learn how to obtain a Synapse API Bearer token, pass it in the Authorization header, and handle token expiry and refresh in integrations.'
---

Every Synapse API request (except the health check endpoint) requires a Bearer token in the `Authorization` header. Your token identifies your account and workspace, and Synapse automatically scopes all data to your tenant — you never need to pass a `tenant_id` manually.

## Get your API token

You can obtain your Bearer token in two ways.

### From the Synapse dashboard

The simplest way to get a token is from your account settings:

<Steps>
  <Step title="Log into the Synapse dashboard">
    Go to [https://app.synapse-architect.com](https://app.synapse-architect.com) and sign in.
  </Step>
  <Step title="Open account settings">
    Click your profile avatar in the top-right corner, then select **Account settings**.
  </Step>
  <Step title="Copy your API token">
    Locate the **API token** field and click **Copy**. Treat this value like a password — do not commit it to source control.
  </Step>
</Steps>

### Via the API (programmatic)

If you are building a server-side integration, you can exchange credentials for a token by calling the Synapse auth endpoint:

```bash
curl -X POST "https://api.synapse-architect.com/api/v1/auth/token" \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "your-password"}'
```

```json
{
  "access_token": "eyJ...",
  "token_type": "Bearer",
  "expires_in": 3600
}
```

<Warning>
  Store tokens securely. Never hard-code them in client-side code or commit them to version control. Use environment variables or a secrets manager.
</Warning>

## Pass the token in requests

Include your token in the `Authorization` header of every request:

```
Authorization: Bearer YOUR_API_TOKEN
```

<ParamField header="Authorization" type="string" required>
  Bearer token obtained from the Synapse dashboard or programmatic auth. Format: `Bearer <token>`.
</ParamField>

## Example requests

<CodeGroup>

```bash curl
curl https://api.synapse-architect.com/api/composio/connected-accounts \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

```typescript TypeScript (fetch)
const response = await fetch(
  'https://api.synapse-architect.com/api/composio/connected-accounts',
  {
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json'
    }
  }
);

if (!response.ok) {
  const error = await response.json();
  throw new Error(error.message);
}

const accounts = await response.json();
```

</CodeGroup>

## Tenant isolation

All data in Synapse is isolated by tenant. When you authenticate, your `tenant_id` is automatically inferred from your JWT — you do not need to include it as a query parameter or request body field. Any attempt to access another tenant's data will be rejected with a `403` error.

## Authentication errors

<ResponseField name="401 Unauthorized" type="object">
  Returned when the `Authorization` header is missing or your token is invalid (e.g., malformed, expired, or revoked). Re-authenticate to obtain a fresh token.
</ResponseField>

<ResponseField name="403 Forbidden" type="object">
  Returned when your token is valid but your account does not have permission to access the requested resource. Check that your subscription tier includes access to the endpoint you are calling.
</ResponseField>

A `401` error response looks like this:

```json
{
  "error": "Unauthorized",
  "message": "Invalid or missing authentication token",
  "code": "AUTH_INVALID_TOKEN",
  "details": {}
}
```

## Token expiry and refresh

Access tokens expire after a set period. When a token expires, requests return a `401` response. To handle expiry gracefully in long-running applications, request a new token before the current one expires and update your stored value:

```typescript
async function refreshToken(email: string, password: string): Promise<string> {
  const response = await fetch(
    'https://api.synapse-architect.com/api/v1/auth/token',
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email, password }),
    }
  );
  const data = await response.json();
  return data.access_token;
}
```

<Note>
  The `expires_in` field in the token response tells you how many seconds until the token expires. Schedule a refresh before that window closes so your integration does not experience authentication errors mid-operation.
</Note>
